# Home Assistant Neptune Apex MonitorBrought to you by [Fullstack Systems](https://fullstacksystems.com).This custom integration pulls real-time probe data from a [Neptune Apex](https://www.neptunesystems.com/) and makes it available in Home Assistant as sensors, feed cycle controls, and diagnostics.![Apex dashboard in Home Assistant: water parameters, feed cycles, Trident reagents and dosing, system status, trends, and outlet mode controls](https://raw.githubusercontent.com/denov/home-assistant-apex-neptune/main/docs/dashboard.png)## Features- Hardware, software and firmware info, with firmware updates from Home Assistant- Auto adds all probes (temperature, pH, ORP, salinity, alkalinity, calcium, magnesium, current, power, voltage, level, flow) and outputs- Outputs: a switch (manual On/Off) and a Mode select (Auto/On/Off) for each output- Apex Alarm: on while an Apex alert output (email alarm, sound alarm, FMM alarm) is on, listing outputs that report an error (e.g. a DOS with "Volt")- DOS/DQD: volume left in each reservoir; set a dosing rate in mL/min- Pumps, lights and variables: intensity, and what a variable's program sets ("Set 75", "Set PF1")- Trident and Trident NP: reagent left (mL, with tests remaining) and waste collected- Energy dashboard support via "Apex Total Energy", and optional energy sensors for outlets that measure power (EB832)- Digital inputs (float, optical, leak switches) as binary sensors- Feed cycles: Feed A–D and Cancel Feed buttons, a Feed Mode sensor (Off/A–D), and a Feed Ends time- Read-only option: monitor only, with no way to change the Apex from Home Assistant- Reads the local status.json from the Apex controller (falls back to status.xml on older firmware)- Configurable F/C for temp- FMM level and flow sensors use the units set on the Apex (inches or cm, gal/h or L/h); without a password, choose them in the options- Works only on the local network, by IP address or hostname (e.g. `apex.local`)- Designed for HACS installEverything that changes the Apex, plus Trident levels, firmware updates and variable settings, uses the ApexREST API and needs the Apex password in the integration settings. Monitoring works without it.If the Apex rejects the password, for example after you change it on the Apex, Home Assistant asks for itagain under **Settings** → **Devices & services**. There you can also remove it to only monitor the Apex.Only current Neptune Systems controllers and modules are supported. An Apex Classic can be monitored, but notcontrolled: it has no REST API. Leave the password empty when you add one.## Controlling outputsEach output has a switch and a **Mode** select. The switch turns the output on or off manually, like ON and OFFon the Apex dashboard. The select also has **Auto**, which hands the output back to its Apex program.The integration also has these actions. Each targets an output's **Mode** entity, so with more than one Apexthere's no doubt which one is meant:| Action | What it does ||---|---|| `apex.set_output` | Sets the output to `AUTO`, `ON` or `OFF`. || `apex.set_variable` | Replaces the output's program, e.g. `Set 75` to run a variable-speed pump at 75%. The output becomes an Advanced output. || `apex.set_dos_rate` | Runs a DOS/DQD pump continuously at a rate in mL/min (0 turns it off). It overwrites the profile you give it and renames it `Dose_<device id>`. |```yamlaction: apex.set_variabletarget:  entity_id: select.apex_return_pump_modedata:  code: Set 75```Programs and profiles changed this way are what the Apex runs, so check them in the Apex dashboard if you'renot sure what an output is doing.## Confirm before feedingIf a feed cycle runs an auto feeder (or anything else you don't want to trigger by accident), have the dashboard ask first.The integration can't do this itself: Home Assistant buttons have no confirmation of their own, so it's set on the dashboard card.In the dashboard editor, open the card and under **Interactions** set **Tap behavior** to *Perform action* → `button.press`with **Require confirmation** on. For a tile card, do the same for **Icon tap behavior**, since tapping the icon pressesthe button immediately otherwise. In YAML:```yamltype: tileentity: button.apex_feed_d   # use your entity IDtap_action: &feed_d  action: perform-action  perform_action: button.press  target:    entity_id: button.apex_feed_d  confirmation:    text: Start Feed D? This also runs the auto feeder.icon_tap_action: *feed_d```This only covers that card: the **Press** button in the entity's dialog, automations, and voice commands don't ask.## Installation### Installation via HACS[![Open your Home Assistant instance and open a repository inside the Home Assistant Community Store.](https://my.home-assistant.io/badges/hacs_repository.svg)](https://my.home-assistant.io/redirect/hacs_repository/?owner=denov&repository=home-assistant-apex-neptune&category=Integration)1. It has what the integration read from your Apex (probes, outputs,modules and configuration), which is usually what's needed to reproduce a problem with your hardware or firmware.1. Go to **Settings** → **Devices & services** and open **Apex Neptune Monitor**.1. Open the **⋮** menu of your Apex entry and choose **Download diagnostics**.1. Attach the downloaded `.json` file to your [GitHub issue](https://github.com/denov/home-assistant-apex-neptune/issues).The file leaves out your Apex password and username, its IP address and serial number, and the Apex's own network,Wi-Fi and email settings. Everything else is included, such as output names and programs, so look it over beforeposting it. Diagnostics need version 1.5.0 or later.If the integration doesn't load, there are no diagnostics to download. Instead, choose **Enable debug logging** onthe integration's page, restart or reproduce the problem, then choose **Disable debug logging** to download the log.## LicenseThis project is licensed under the **GNU Affero General Public License v3.0 or later**(**AGPL-3.0-or-later**).
